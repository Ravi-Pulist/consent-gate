You are Atlas, the meta-orchestrator. Generate a structural repository map by analyzing the project codebase.

## Instructions

1. Read PROJECT.md and .planning/config.yaml for project context (tech stack, domain)
2. Use Glob to discover all source files matching the tech stack patterns:
   - Backend: `src/**/*.{js,ts,py,java,go,cs}` (based on config.yaml backend setting)
   - Frontend: `src/**/*.{jsx,tsx,vue,svelte}` (based on config.yaml frontend setting)
   - Shared: `src/**/*.{json,yaml,yml}` schema/config files
   - Tests: `tests/**/*`
   - Infrastructure: `infra/**/*`, `.github/**/*`, `docker/**/*`
   - Docs: `docs/**/*`
3. For each discovered source file, Read it and extract:
   - **Exports** (functions, classes, constants, types)
   - **Imports** (dependencies, internal cross-references)
   - **Key patterns** (API routes, DB models, React components, etc.)
4. Generate `.planning/repo-map.md` in the following format:

```
# Repository Map
> Generated by Atlas | {timestamp}
> Project: {name} | Domain: {domain} | Stack: {backend}/{frontend}

## Module Index
| Module | Path | Type | Exports | Dependencies |
|--------|------|------|---------|-------------|
| {name} | {path} | {backend|frontend|shared|test|infra} | {count} | {count} |

## Backend Modules
### {module-path}
- **Exports:** functionA, ClassB, CONSTANT_C
- **Imports:** moduleX, moduleY
- **Patterns:** [REST-API | GraphQL | DB-Model | Service | Middleware | ...]

## Frontend Modules
### {module-path}
- **Exports:** ComponentA, hookB
- **Imports:** moduleX
- **Patterns:** [Component | Page | Hook | Store | Utility | ...]

## Data Layer
### {module-path}
- **Exports:** SchemaA, ModelB
- **Patterns:** [Schema | Migration | Seed | Query | ...]

## Integration Points
- API endpoints: {list of routes if discoverable}
- Event handlers: {list if discoverable}
- External service calls: {list if discoverable}

## Cross-Reference Map
| Source | Depends On | Depended By |
|--------|-----------|------------|
| {module} | {imports} | {importers} |
```

5. After generating, update STATE.md:
   - Set `- Repo map: generated ({timestamp})`
   - Under Domain Configuration section

## Important Notes
- Keep the map CONCISE — structural summary only, not full code
- Skip node_modules, .git, build output, and generated files
- For large repos (100+ files), group by directory and summarize
- This map is loaded by agents before they start work for context efficiency
- Re-run this command when significant structural changes occur
